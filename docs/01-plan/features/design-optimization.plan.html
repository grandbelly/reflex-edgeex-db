6. 단계 (Phases) — 재정렬

검토 G4 반영: rx.color/브릿지 결판을 Phase 1로 끌어올림. 초안은 rx.color 정산을 Phase 4에 두면서 Phase 3 파일럿 acceptance("대시보드 라이트/다크 정상")가 그것을 선결로 요구하는 모순이 있었음.

Phase 1 — 토큰 기반 + 토글 브릿지 + rx.color 전략 결판

목표: --am-* 도입 + data-theme 실동작 + rx.color 듀얼테마 메커니즘 확정(프레임/배선 먼저).

OPT-01, OPT-14, OPT-02, OPT-03, OPT-13(전략 결정+PoC)
Outcome: 헤더 토글/DevTools 로 <html data-theme> 가 라이트↔다크 전환, --am-* 일괄 뒤집힘, rx.color 컴포넌트 1개 PoC로 양테마 검증. --ks-* 화면 무회귀. localStorage 영속, FOUC 없음.

Phase 2 — 공용 컴포넌트 토큰화

목표: 카드/배지/버튼/검색/사이드바를 --am-* 참조로 → 전역 셸 듀얼테마.

OPT-04, OPT-05, OPT-07
Outcome: am_* 1모듈 가동, 공통 사이드바/헤더 양테마 자연 전환, dead/orphan 제거로 혼선 종결.

Phase 3 — 1차 화면 적용·검증 (대시보드 + 트렌드)

목표: 가장 많이 쓰는 화면을 Apple-mode 로, OPT-13 전략을 실전 적용·실측.

OPT-06, OPT-15(대시보드+트렌드 우선)
Outcome: 대시보드·트렌드가 양테마 무파손 렌더(스크린샷 비교). 이후 화면 복제용 레퍼런스 패턴(am_card+rx.color 처리) 확정.

Phase 4 — 보조 화면 확대 + 정리

목표: 분석 화면·위저드·차트·접근성·중복카드 점진 토큰화 + 부채 정리.

OPT-15(위저드 잔여), OPT-08, OPT-09, OPT-10, OPT-11, OPT-12
Outcome: 핵심+보조 듀얼테마 일관, 차트/focus/모션 토큰 정합, KPI 카드 수렴, orphan 정리. SCADA 전용 화면은 openQuestion 결정 따름.

styles.css :62-88 다크전용 오버라이드가 라이트 모드 전역 파괴(.bg-white→navy).OPT-14 로 [data-theme='dark'] 스코핑(P0).
Radix Themes 자체 라이트색이 --am-* 와 충돌..rt-Card 오버라이드를 data-theme 별 확장 + 필요부만 !important. appearance 는 구조용, 색은 CSS 변수 통제.
design_system.py 삭제 시 동명 패키지(데모가 import)와 혼동 → 잘못 삭제.삭제 전 정확 경로 확인(파일 vs 패키지), 데모 페이지 orphan 동시 처리(OPT-12).
혼합 appearance 구간 a11y 회귀(focus/대비) — 단일 파일은 멀쩡해 보여도 WCAG 미달.화면 단위 완결 전환 + OPT-10 focus/대비 검증을 전환 게이트에 포함.
