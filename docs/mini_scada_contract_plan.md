# 미니 SCADA 공통 데이터 계약 전환

오너 지시: 미니 SCADA 전체 재검토 뒤 “계속 진행한다”(2026-10-27). 기준 dd958d7.

2026-10-28 추가 지시로 **[메뉴별 시각화 계약](mini_scada_visualization_contract.md)**을 화면 정보 설계의 우선 기준으로 삼는다. 공식 템플릿 스터디는 [reflex_template_study.md](reflex_template_study.md). 오너 선택은 stock_market_dashboard의 관제 배치와 stock_graph_app의 실시간 그래프다. 아래 첫 수용 단위는 데이터 기반 검증이며 메뉴별 UX 완료를 뜻하지 않는다.

## 첫 수용 단위

기존 상위 Kafka 연계(CR277)의 VQT를 여섯 메뉴에서 같은 현장·태그·품질·시각으로 읽는다. 운전 Consumer/설치본/채널/브로커/컨테이너 변경 없이 별도 worktree와 localhost 검증 앱을 사용한다. 새 CR 번호를 임의 발급하거나 엣지 제품 범위를 확장하지 않는다.

`SCADA_DATA_SOURCE=edge_vqt` 조회 프로필로 전환한다. 2026-10-28 오너의 최신 Reflex·템플릿 지시로 새 앱의 기본 진입점도 이 프로필로 한정한다. 기존 3100/8100 설치 트리와 venv는 보존한다. SQL 오류 때 legacy 자료로 우회하지 않는다. 새 화면의 근거와 이관 기준은 `docs/reflex_template_source.md`에 적는다.

## 계약

- 모든 조회에 site_id 필수, 태그 키 (site_id, tag_id). SQL 바인딩 사용.
- RAW/COND/FINAL의 NULL, 실제 0, 기존 품질 0/1/2를 보존한다. 화면은 알 수 없는 수치를 `—`로 표시한다.
- 통신·현재성·품질·공정 경보·조회 상태를 구분한다. VQT 행 존재로 브로커/PLC 정상 판정 금지.
- 태그 정의/설비 연결/수집 계획이 전달되지 않은 상태를 표시한다. 관측 태그 수를 기대 태그 수로 쓰지 않는다. 수집 성공률의 분모를 추정하지 않는다.
- Health·경보 선택 기능의 스키마/조회 실패는 해당 절에 표시하고 VQT 조회는 계속한다. UI에 SQL 원문을 노출하지 않는다.
- 같은 응답은 짧은 read-only REPEATABLE READ 트랜잭션으로 구성한다. 응답 기준시각은 장치의 동시 측정을 보장하지 않는다.
- 원천 시각과 상위 적재 시각을 분리한다. 과거 보충으로 현재성 판정 갱신 금지.
- 트렌드는 최근 범위에서 상한 표본만 조회하고 잘림을 표시한다. NULL 구간 연결 금지. 장기 집계는 다음 단위다.
- 경보는 원천 발생/복귀/확인을 읽는다. 인증 사용자/ACK 소유권 계약 전에는 새 프로필에서 쓰기 기능을 노출하지 않는다. 앱 내 Consumer·스케줄러와 구형 수정 경로를 등록하지 않는다.
- 프로필/스키마 불일치는 차단 사유다. 앱에서 DDL·시드 데이터 생성 금지.

## 메뉴별 데이터 계약

|메뉴|첫 단위의 근거|누락 때 표현|
|---|---|---|
|운전 개요|선택 현장 최신 VQT·품질·원천 시각|조회 오류/표본 없음/정의 미수신|
|공정 감시|같은 최신 태그와 채널|공정 모델 미수신, 정적 공정도 정상 표시 금지|

|경보|선택 현장 원천 사건 최근100건|조회 오류와 경보0건 분리|
|데이터 흐름|선택 현장 VQT 적재·Health 근거|관측하지 못한 PLC/Kafka 상태는 —|
|통신 이력|선택 기간의 실제 VQT 표본·품질 수|계획 없는 성공률/완전성은 —|

## 검증

불변식 시험: NULL/0·비유한값, BAD, 오래된 원천/새 적재, 현장·태그 충돌, 미래 시각, 필수 스키마 부재, Health 단독 실패, 읽기 전용/선택기능 savepoint, 표본 상한·시간 범위. 실제 상위 DB는 읽기 전용으로 원시 조회와 서비스 출력을 같은 응답에서 대조한다. 원천/운전 장애 주입은 하지 않는다. 변이는 격리된 메모리 코드에만 적용한다.

Windows 전용 검증 venv에서 표적 시험·컴파일·Reflex 빌드·orca computer 화면을 확인한다. 기존 Docker 시험 지침은 컨테이너 변경0인 이번 범위에 적용하지 않으며, 운영 배포·RPI·실제 장애 복구 수용은 별도다.

## 다음 수용 단위

정본 태그 정의·버전 동기화, 공정 모델 바인딩, 계획 기반 통신 완전성, 장기 집계·지연 정정, 인증된 ACK 동기화, 공유 조회 캐시와 다중 접속 부하, 운전 전환. 이 단위들의 미완료를 첫 단위의 PASS로 덮지 않는다.
