# 미니 SCADA 메뉴별 시각화 계약

2026-10-28 오너 지시: “메뉴별 시각화 철학이 다 사라졌다. 무엇을 시각화해야 하는지부터 명확히 정의하고 메뉴별로 구분해라.” 이 문서가 템플릿·컴포넌트 배치보다 먼저 적용되는 정보 설계다. 구현 완료 성적서가 아니다.

## 목표와 확인한 사실

사용자가 각 메뉴에서 서로 다른 판단을 끝낼 수 있어야 한다. 현재 공통 조회 프로필은 현장·NULL·품질·시각 계약을 바로잡았지만, 대시보드/워크플로우/관제에 비슷한 태그 표를 반복해 역할을 약화시켰다. 데이터 계약 시험16개·106점 대조 통과는 이 문제를 해결했다는 증거가 아니다.

기존 정본 코드의 의도도 확인했다. `pages/dashboard.py`는 계층·그룹별 현황, `pages/workflow.py`는 PLC→저장/집계→QC/알람→예측/시뮬레이션→제어 출력의 폐루프, `pages/trend_enhanced_v2.py`는 시계열 분석, `pages/alarms.py`는 경보 대응, `pages/communication.py`는 시간대별 통신 히트맵, `pages/edge_monitor.py`는 Kafka VQT·경보·Health 수신 관제였다. 예전 workflow의 2026-06-17 정적 수치·상시 흐름 애니메이션을 현재 운영 사실로 복원해서는 안 된다.

메뉴 이름은 기존 업무 개념인 **대시보드·워크플로우·트렌드·알람·통신 상태·Edge 관제**로 유지한다. 의미가 좁아지는 임의 개명(워크플로우→태그 목록, Edge 관제→범용 데이터 흐름)은 되돌릴 대상이다. URL은 기존 여섯 경로를 유지한다.

## 경계와 시각화 원칙

워크플로우는 **업무·공정 판단과 조치의 관계**를, Edge 관제는 **자료 전달과 처리의 신뢰성**을 보여준다. 통신 상태는 장치·채널의 연결 이력을 맡는다. 상위에 행이 있다는 사실을 세 메뉴의 동일한 정상 근거로 재사용하지 않는다.

대시보드는 주의·의사결정의 입구다. 전체 태그 표와 커다란 분석 그래프가 첫 화면을 차지하지 않게 한다. 전체 태그 탐색은 Edge 관제의 표본 드릴다운과 트렌드 선택 도구로 배치한다. 상세 화면은 선택 현장/설비/태그/사건/시간을 전달받는다.

색은 의미를 고정한다. 공정 경보 우선순위, 데이터 품질, 현재성, 통신 연결, 조회 가능 여부는 별도 축이다. 예: GOOD이지만 오래된 표본, 통신 연결이지만 BAD인 값, 조회 성공이지만 Health 미수신을 함께 표현할 수 있어야 한다. 회색의 미확인·미연결은 정상 초록과 구분한다. 수치 증감의 초록/빨강은 운전 정상/이상을 뜻하지 않는다.

한 화면 안에서 요약→주 시각화→선택 상세로 읽히도록 한다. 카드·표·차트의 크기와 밀도는 이 위계에 따른다. 같은 KPI와 전체 태그 표를 여섯 메뉴의 본문으로 반복하지 않는다. 공통 요소는 탐색·컨텍스트·색 의미·서체·간격·오류/빈 자료 규칙이다.

값과 시간의 진실은 모든 메뉴에 적용한다. NULL과 실제0을 구별하고, 음수를 축에서 잘라내지 않으며, 결측을 부드러운 선으로 메우지 않는다. source time·ingested time·조회 기준·브라우저 갱신을 구분한다. 여러 태그를 같은 조회로 받았다고 동시 측정이라고 쓰지 않는다. 표본 상한/집계/구간 생략·지연 도착·보정은 보이게 한다.

## 데이터가 아직 없는 메뉴의 표현

미수신 정보를 채우기 위해 임의 공정도·상태·한계·진행률을 만들지 않는다. 해당 시각화 자리에서 연결되지 않은 계약과 필요한 자료를 좁혀 표시하고 관련 기능 상태를 명시한다. 다른 메뉴의 전체 태그 표로 본문을 대신하지 않는다.

현재 실제 연결된 것은 site별 상위 VQT, 최근 경보 일부다. `edgeex_health_latest` 부재, 기대 태그/설비/워크플로우 정의·수집 시도/응답 계획·단계별 전달 지표·ACK 소유권 연결은 미완료다. 현장별 필요한 모델이 달라질 수 있으므로 RO 설비와 모든 SY 태그를 자동으로 동일 모델에 매핑하지 않는다.

과거 workflow의 AI/PLC writeback은 기능 연결/승인 근거가 있을 때만 동작 상태를 표시한다. 이번 읽기 전용 프로필에서 제어·확인 명령을 추가하거나 운영 설정을 바꾸지 않는다. 단순히 메뉴에서 지운 뒤 기능이 없었다고 취급하지 않고 연결 상태를 남긴다.

## 템플릿의 쓰임

오너가 선택한 [stock_market_dashboard](https://github.com/reflex-dev/templates/tree/e56a1a065208924dada4d23c769d15114381c6b5/stock_market_dashboard)는 고밀도 관제의 배치·탐색·표·선택 상세 참고다. [stock_graph_app](https://github.com/reflex-dev/templates/tree/e56a1a065208924dada4d23c769d15114381c6b5/stock_graph_app)은 트렌드의 현재값 헤더·기간 선택·영역 그래프·tooltip·갱신 참고다. 스터디는 [reflex_template_study.md](reflex_template_study.md).

템플릿의 적용 범위는 위 시각화 역할에 따른다. 모든 메뉴를 주식 화면으로 복제하지 않는다. 대시보드의 우선 조치, workflow의 흐름도, 통신의 히트맵, 관제의 계층별 처리 상태는 각각 목적에 맞는 시각화가 필요하다. 모든 버튼은 실제 지원 동작과 연결한다.

## 구현 단위와 검수

공통 `ScadaContext`는 site·설비/태그/사건 선택·시간·live/fixed와 snapshot metadata를 맡는다. 메뉴별 State/서비스는 해당 목적에 필요한 자료와 상태를 맡는다. 조회 불변식·스타일·선택 컨텍스트를 공유하되 모든 메뉴에서 무조건 같은 큰 snapshot(태그 전체+이력+경보+Health)을 5초마다 조회하는 구조는 이관 대상으로 삼는다.

순서: 이 메뉴 계약·필수 자료/미연결 범위를 먼저 확정 → 현재 연결 자료로 구현 가능한 화면부터 목적에 맞게 구성 → 실제 캡처로 원본 템플릿의 위계·정렬·조작을 비교 → 메뉴별 운영 시나리오와 독립 자료 대조 → 최종 SHA/영수증/PR. 자료가 없어 실행 못 한 시나리오는 미검증으로 남긴다.
