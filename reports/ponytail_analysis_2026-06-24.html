작동 원리: 사다리 (The Ladder)

코드 작성 전, 첫 번째 유지되는 rung에서 멈춥니다:

1
존재할 필요가 있는가? → 없다: 스킵 (YAGNI)
2
이미 코드베이스에 있는가? → 재사용, 재작성 금지
3
표준 라이브러리가 하는가? → 그걸 사용
4
네이티브 플랫폼 기능인가? → 그걸 사용
5
설치된 의존성이 있는가? → 그걸 사용
6
한 줄로 가능한가? → 한 줄로 작성
7
그 다음: 동작하는 최소한만
⚠️ Lazy ≠ Negligent
신뢰 경계 검증, 데이터 손실 처리, 보안, 접근성은 절대 줄이지 않습니다.

🔧 실전 적용 예시

사례 1: PLC 알람 히스토리 페이지 추가

📋 상황 분석
1. 필요한가? ✅ Yes (사용자 요청)
2. 이미 있는가? ❌ No (알람 페이지 있음, 히스토리 없음)
3. 표준 라이브러리? Python logging, datetime ✅
4. 네이티브 기능? TimescaleDB time_bucket ✅
5. 설치된 의존성? Reflex Table, Radix ✅
6. 한 줄? No
7. 최소한: 간단한 SELECT + Table UI만

결과: 200줄 예산 → 50줄로 구현 (기존 알람 state 재사용)

사례 2: 코드 비교

State Management

# ❌ 하지 말 것
class AlarmHistoryState(rx.State):
    def get_alarms(self):
        # 새로운 fetch 로직 작성...
        pass

# ✅ Ponytail 방식
class AlarmHistoryState(rx.State):
    alarms = State.list  # 기존 AlarmState 재사용
    def fetch_alarms(self):
        # 이미 있는 get_alarms() 호출
        return AlarmState.get_alarms()

UI Components

# ❌ 하지 말 것
# custom_slider_library 설치 후...
import custom_slider
slider = custom_slider.Slider(min=0, max=100)

# ✅ Ponytail 방식
# Radix 내장 활용
rx.slider(
    min=0,
    max=100,
    default_value=50,
    on_change=handle_change
)

Database Queries

# ❌ 하지 말 것
# 새 테이블 + 복잡한 JOIN...
CREATE TABLE alarm_history_partitioned [...]
SELECT * FROM alarms a
JOIN alarm_history h ON a.id = h.alarm_id
WHERE ...

# ✅ Ponytail 방식
# Hypertable 이미 시간순 자동 partition
SELECT * FROM alarms
WHERE time > NOW() - INTERVAL '1 hour'
ORDER BY time DESC

Styling

# ❌ 하지 말 것
style={"color: #36E2C0"}  # 하드코딩

# ✅ Ponytail 방식
style={"color: var(--ks-aqua)"}  # 기존 변수 재사용

⚙️ 설치 및 설정

✅ 이미 설치됨 - 다음 명령어로 모드 제어

명령어

  • /ponytail ultra - 최대 절약 모드
  • /ponytail full - 기본값 (권장)
  • /ponytail lite - 가벼운 절약
  • /ponytail off - 끄기
  • /ponytail-review - 현재 diff 오버엔지니어링 검토
  • /ponytail-audit - 전체 리포지터리 감사
  • /ponytail-help - 도움말

기본값 설정 (모든 세션)

# 환경변수
export PONYTAIL_DEFAULT_MODE=full

# 또는 설정 파일 (Windows: %APPDATA%\ponytail\config.json)
echo '{"defaultMode": "full"}' > ~/.config/ponytail/config.json
