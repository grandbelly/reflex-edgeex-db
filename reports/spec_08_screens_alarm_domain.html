상태별 UI 표현

  • loading state: 전체 content 영역을 rx.center 스피너로 교체. Refresh 버튼 loading=True로 disabled + 스피너. 사용자 액션 (view toggle, filter) 가능하나 데이터 갱신은 대기.
  • error state: AlarmsState.error_message != ""일 때 red callout 표시 (표 위). dismiss 불가 (조건부 렌더만). 표는 그대로 유지 (이전 데이터 표시).
  • empty state (history): rx.center → inbox 아이콘 + "No alarms found" + "Try adjusting the filters or time range". AlarmsState.total_count == 0일 때.
  • populated state: 알람 rows foreach 렌더. CRITICAL rows: rgba(239,68,68,0.1) + 4px red left border. WARNING: rgba(245,158,11,0.1) + 4px amber. NORMAL: white.

Edge Cases

케이스 현재 처리 평가
알람 0개 (empty) inbox 아이콘 + 텍스트 정상 처리
알람 1000개+ server-side pagination (page_size=20) 정상 — total_count 기반 페이지 계산
DB 연결 끊김 error_message callout 처리됨 — @event_with_error 래퍼
WebSocket 끊김 처리 없음 (DashboardRealtimeState 의존) 결함 — 재연결 로직 없음
acknowledge 중 중복 클릭 처리 없음 (버튼 disable 없음) 결함 — race condition 가능
동일 alarm 이중 acknowledge DB: UPDATE WHERE acknowledged=false 안전 — WHERE 조건으로 중복 방지
filter 변경 중 페이지 이동 page=1 리셋 후 서버 재조회 정상
search_query + page 동시 변경 각각 독립 background event 경쟁 조건 가능 (큐잉 없음)

Responsive 대응

  • desktop (≥1280px): 4열 KPI 카드 + 전체 테이블 정상 표시
  • tablet (768-1279px): KPI 카드 4열 유지 (columns="4" 고정). 테이블 수평 스크롤 없음 — width 오버플로우 가능
  • mobile (<768px): stat_card columns="4" 고정으로 레이아웃 깨짐 예상. 테이블 컬럼 압축 없음 — 미대응
