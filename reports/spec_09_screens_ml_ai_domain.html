1.5 Event Handler 매핑

Handler 트리거 비동기? 설명
load_deployed_models on_load background 배포 모델 목록 + 첫 모델 자동 선택 + 예측 로드
start_countdown_monitor on_load background 30초마다 DB poll, 새 forecast_time 감지 시 reload
select_model(model_id) Select onChange sync 모델 선택 → load_predictions 반환
load_predictions 새로고침 버튼 background _load_predictions_internal() 호출
_load_predictions_internal 내부 async (internal) DB에서 rolling_window_data + 메트릭 계산

stop_streaming (구현 있지만 UI 없음) sync is_streaming=False
toggle_y_axis_scale Y축 토글 버튼 sync y_axis_from_zero 토글
trigger_forecast_now (구현 있지만 UI 없음) background docker exec forecast-scheduler 직접 실행

Y축 스케일 토글 동작: - y_axis_from_zero=True (기본): min=0, max=data_max+5% - y_axis_from_zero=False (자동): min=data_min-5%, max=data_max+5% - CI 밴드 상하한도 domain 계산에 포함

모델 드롭다운 → 메트릭 카드 reactive 관계:

select_model(id) → load_predictions → _load_predictions_internal
  → rolling_window_data 갱신 → chart_data 변경 → chart 재렌더
  → cached_mape/rmse/nrmse/accuracy 갱신 → mape_display/r2_display/accuracy_% 변경 → 카드 재렌더

시간 범위 selector: 없음 — rolling window 고정 (T-30 ~ T+horizons). 사용자가 범위를 조정하는 UI 없음.

1.9 알려진 결함

ID 심각도 설명
F-01 High error_message state var가 있지만 forecast_player.py 페이지에 error callout 컴포넌트 없음 → 에러 발생 시 사용자에게 무음 실패
F-02 Medium scheduler_running var가 항상 True 하드코딩 — 실제 스케줄러 중단 시에도 "정상 작동" 뱃지 표시

F-04 Medium r2_display var 이름이 R² Score이지만 실제로는 NRMSE (CV-RMSE) 값을 표시 — 라벨과 값 불일치 ("NRMSE" 카드 제목이지만 var name은 r2_display)
F-05 Low countdown_seconds 항상 600으로 초기화됨 — start_countdown_monitor가 on_load에서 시작되지만 is_streaming=False이므로 루프 즉시 종료. 카운트다운이 실제로 동작하지 않을 가능성 있음
F-06 Low colspan="66" 하드코딩 (MAPE 행) — 데이터 포인트 수에 따라 잘못된 colspan이 될 수 있음
F-07 Low 데이터 테이블 height=400px 고정 — 화면 크기에 따른 반응형 없음

3.5 Pickle Cache 동작

TrainingState.start_training() 완료
  → _cache_training_result(selected_tag, result, best_model)
  → 모듈 레벨 dict에 저장 (Python process 메모리)

TrainingState.save_model()
  → _get_cached_model(selected_tag)
  → pickle.dumps(trained_model)  [asyncio.to_thread 비동기 실행]
  → PostgreSQL model_registry.model_pickle (BYTEA)

메모리 휘발 시나리오: - Docker 컨테이너 restart → 모듈 레벨 cache 소멸 - save_model 클릭 전에 restart 시 → _get_cached_model = None → "metadata only" 저장 (모델 객체 없이) - 이 경우 해당 모델은 ForecastScheduler에서 로드 불가 → 배포해도 예측 실패 - Wizard 재시작 필요: reset_wizard() 후 처음부터 다시 학습

S4.3 Validation Feasibility 계산 로직

test_size = (forecast_horizon_hours * 60) / forecast_interval_minutes
estimated_samples = (training_days * 24 * 60) / forecast_interval_minutes
max_n_splits = (estimated_samples // test_size) - 1
n_splits = max(3, min(max_n_splits, 10))
min_required = (n_splits + 1) * test_size
shortage = min_required - estimated_samples

shortage > 0          → error (데이터 부족)
0 < -shortage < 100   → warning (Tight fit)
-shortage >= 100      → success

S6.2 save_model 동작 흐름

click [Save Model]
  → TrainingState.save_model() (@rx.event background=True)
  → is_loading = True

  (1) current_time = datetime.now() [단 1회 캡처]
  (2) model_name = f"{model}_{tag}_{YYYYMMDD_HHMMSS}"
  (3) _get_cached_model(selected_tag) → pickle bytes (asyncio.to_thread)
  (4) version = f"1.0.{YYYYMMDDHHMMSS}"
  (5) data_start/end → datetime 파싱
  (6) pipeline_config dict 구성
      forecast_config: {interval, horizon, horizons[], total_steps}
      metrics: {validation_data, mape, mae, rmse, ...}
      training_info: {data_start, end, samples, duration, ...}
      hyperparameters: {training_days, feature_config_id, ...}
  (7) ModelRegistry INSERT (BYTEA pickle, metrics)
  (8) session.flush() → model_entry.model_id 획득
  (9) training_evaluation BULK INSERT (N개 horizon 레코드, 1 round-trip)
       evaluation_time = current_time
       target_time = current_time + timedelta(minutes=horizon_minutes)
       actual_value = 0 (placeholder)
  (10) session.commit()
  (11) 저장 확인 쿼리 → saved_model_info / saved_predictions 업데이트
  (12) show_saved_data = True
  (13) rx.toast.success() 표시
  → is_loading = False
