FN-ALM-01 M1 BG
실시간 알람 단건 acknowledge
State: AlarmsState · Handler: acknowledge_alarm(event_id: str) @ alarms.py:588 · 라우트: /alarms · Service: AlarmService.acknowledge_alarm · DB: alarm_history
운영자가 활성 알람 row 의 "확인" 버튼을 클릭하여 해당 알람을 acknowledged 상태로 전환. Day 7 의 @event_with_error decorator 적용된 첫 PoC 대상.

Input

이름타입출처제약
event_idstr알람 row.event_id (UUID 또는 alarm_history.event_id)NOT NULL · 36자 UUID 또는 합성 ID 포맷

Process

  1. get_async_session() 으로 SQLAlchemy AsyncSession 획득
  2. AlarmService(session).acknowledge_alarm(event_id, "user") 호출
  3. Service 내부: UPDATE alarm_history SET acknowledged=true, acknowledged_at=NOW(), acknowledged_by='user' WHERE event_id=:eid
  4. 성공 시 self.refresh_data() 로 화면 재조회
  5. 실패 시 self.error_message 에 메시지 설정, UI 표시

Output

  • DB: alarm_history row 의 acknowledged=true, acknowledged_at=NOW(), acknowledged_by='user'
  • UI: 해당 row 가 active 뷰에서 사라지고 history 뷰로 이동 (filter 재계산)
  • State: active_count 감소, history_count 증가

Pre-conditions

  • 해당 event_id 가 alarm_history 에 존재
  • 사용자가 /alarms 페이지에 로그인 (현재 인증 없음 — 누구나 가능)

Post-conditions

  • alarm_history.acknowledged_at IS NOT NULL
  • 해당 row 가 active_alarms @rx.var 결과에서 제외됨
  • idempotent: 이미 acknowledged 인 경우 UPDATE 0 rows (silent no-op)

Business Rules

  • acknowledged_by 는 현재 하드코딩 "user" — 향후 인증 도입 시 실제 user identity 로 교체 (M2)
  • 한번 acknowledged 된 알람은 unacknowledge 불가 (audit trail 정책)

Error Handling

  • event_id not found → DB UPDATE 0 rows (silently no-op, UI 변화 없음)
  • DB 연결 실패 → @event_with_error decorator 가 catch, error_message 설정
  • UI 토스트 메시지 미구현 (M2 backlog)

Cross-references

  • UI: spec_08 Page 1 (Alarm History)
  • Storyboard: spec_07 OP-01 Step 4 (일괄 acknowledge), OP-02 Step 6 (긴급 단건 ack)
  • Test: TC-ALARM-03 (spec_05)
  • Audit: Day 7 @event_with_error decorator PoC 적용 (commit 898c299)
