1. 인프라 개요 — Compose 서비스 토폴로지

3. Provisioning / Deploy 시나리오

OP-001: RPI 첫 배포 (Fresh Provisioning) PROV

속성값
운영 IDOP-001
분류Provisioning / 1회성
책임System Administrator
예상 소요30분 (네트워크 + 첫 빌드 포함)
전제조건RPI 5 (ARM64), Raspbian/Debian 부팅, ssh key auth 설정, 인터넷 연결, 신규 Cloudflare tunnel 토큰 발급 완료
관련 도구scripts/bootstrap_rpi.sh, scripts/restore_db.sh, scripts/measure_rpi_baseline.sh

단계별 절차

  1. ssh tion@<new-rpi-ip> 접속
  2. 코드 배포 — git clone 또는 scp tarball: 
    rsync -avz --exclude .git --exclude .web --exclude saved_models \
  ./reflex-rpi-local-deployment-poongdo/ \
  tion@<new-rpi-ip>:/home/tion/deployment/20251030-rpi-finished/
  3. bootstrap 1차 실행 (Docker 설치 + .env scaffold + POSTGRES_PASSWORD 자동생성): 
    cd /home/tion/deployment/20251030-rpi-finished/
./scripts/bootstrap_rpi.sh
    스크립트가 자동으로:
    • OS sanity check (ARM64, Debian, internet ping 1.1.1.1)
    • Docker + compose-plugin idempotent 설치
    • .env.example → .env 복사 후 POSTGRES_PASSWORD 24자 랜덤 생성 (openssl)
    • chmod 600 .env
    • CLOUDFLARE_TUNNEL_TOKEN + RPI_NODE_ID 미입력 시 종료코드 10으로 중단
  4. 운영자가 .env 수동 보완: 
    nano /home/tion/deployment/20251030-rpi-finished/.env
# (앞에 스페이스 한 칸 → bash history 회피)
# CLOUDFLARE_TUNNEL_TOKEN=eyJh...
# RPI_NODE_ID=pd-site-001
  5. POSTGRES_PASSWORD 즉시 비밀번호 관리자에 저장: 
    grep ^POSTGRES_PASSWORD= .env
    이 값은 자동 로그되지 않음 — 운영자가 직접 보관.
  6. bootstrap 2차 실행 (검증 통과 → 이미지 pre-pull): 
    ./scripts/bootstrap_rpi.sh
  7. DB 컨테이너만 먼저 기동: 
    docker compose up -d rpi-finished-pgai-db
  8. 기존 RPI에서 dump 전송 (운영자 PC 거치지 않는 직송 rsync): 
    ssh tion@<old-rpi> "docker exec rpi-finished-pgai-db pg_dump -Fc -U postgres ecoanp > /tmp/ecoanp.dump"
rsync -avz --remove-source-files tion@<old-rpi>:/tmp/ecoanp.dump /tmp/
  9. TimescaleDB-aware 복원: 
    ./scripts/restore_db.sh /tmp/ecoanp.dump
    6단계 자동 진행 (DROP/CREATE → CREATE EXTENSION → pre_restore → pg_restore single-thread --no-owner --no-privileges → post_restore → 행 수 sanity check).
  10. 나머지 5 서비스 기동: 
    docker compose up -d
  11. Baseline 측정: 
    ./scripts/measure_rpi_baseline.sh
# → reports/rpi_baseline_<hostname>_<date>.txt
  12. 네트워크 안정성 확인 후 SSH 하드닝: 
    ./scripts/bootstrap_rpi.sh --harden
# password auth 비활성 + ufw 활성 (22/tcp 만 허용)
    경고: 키 로그인 검증 전엔 절대 logout 금지.

검증

  • curl http://localhost:14000/ → HTTP 200, < 2초
  • docker ps --format 'table {{.Names}}\t{{.Status}}' → 6 서비스 모두 Up (db healthy)
  • docker logs cloudflared-tunnel --tail 20 | grep -i registered → connection 등록 확인
  • Cloudflare Zero Trust dashboard → Tunnels 화면에서 새 노드 ONLINE
  • ./scripts/measure_rpi_baseline.sh 결과의 7. SD card random write 50MB/s 이상

롤백

Fresh RPI이므로 단순 SD 재플래시. 또는 docker compose down -v (volume까지 삭제) 후 처음부터.

알려진 함정

  • POSTGRES_PASSWORD 분실 — 자동생성 후 즉시 캡처해야 함. 분실 시 DB 재시작 불가, 데이터 손실 (volume 삭제 필요).
  • Cloudflare 토큰 재사용 금지 — 기존 RPI 토큰 그대로 쓰면 두 노드가 같은 hostname으로 등록되어 라우팅 불안정.
  • pg_cron 1.6.7 + PG17 ABI 미스매치 — Dockerfile.rpi-pgcron 그대로 사용 (HANDOFF.md 참조). 임의 pg_cron 업그레이드 금지.
  • parallel pg_restore 금지 — TimescaleDB hypertable이 TRUNCATE ONLY와 호환 안 됨. restore_db.sh는 single-thread 고정.
  • edgeex-network가 external이므로 첫 기동 전 docker network create edgeex-network 필요.

롤백

cd /home/tion/deployment/20251030-rpi-finished/
git checkout HEAD~1 -- edgeex_app/states/forecast_player_state.py

알려진 함정

OP-003: 이미지 재빌드 (requirements/Dockerfile 변경) PROV

운영 IDOP-003
분류Provisioning / 수시
책임DevOps
예상 소요15분 (RPI ARM64 빌드 느림)
전제조건requirements*.txt / Dockerfile* / 빌드 컨텍스트(20251030-rpi-pgcron/) 중 하나 변경됨, 디스크 여유 2GB+
관련 도구docker compose build, docker system prune

단계별 절차

  1. 대상 식별 (어느 이미지가 영향받는지): 
    git diff HEAD~1 -- requirements.txt Dockerfile*
  2. 대상 서비스만 빌드 (전체 빌드 1시간 vs 단일 15분): 
    cd /home/tion/deployment/20251030-rpi-finished/
docker compose build --no-cache rpi-finished-reflex-app
# DB 이미지 변경시:
docker compose build rpi-finished-pgai-db
  3. 새 이미지로 재기동 (volume 보존): 
    docker compose up -d --no-deps --force-recreate rpi-finished-reflex-app
  4. 구 dangling image 정리: 
    docker image prune -f

검증

  • docker images | grep rpi-finished → 최신 빌드 시각 확인
  • OP-020 일일 health check 전체 통과

롤백

# 이전 이미지 태그 보관해뒀다면:
docker tag rpi-finished-reflex-app:prev rpi-finished-reflex-app:latest
docker compose up -d --force-recreate rpi-finished-reflex-app
# 아니면 git revert + 재빌드

알려진 함정

  • RPI에서 빌드 시 SD wear — 빈번한 --no-cache 빌드는 SD 카드 수명 깎음. 외부 ARM64 빌드머신 (BuildKit + buildx remote) 고려.
  • 메모리 부족 OOM — Reflex 빌드 중 npm install이 ~1.5GB 점유. swapon --show로 swap 4GB+ 확보.
  • multi-arch base image — Dockerfile FROM이 amd64 manifest만 가지면 RPI에서 실패. --platform linux/arm64 명시.

  2. NOTIFY/LISTEN 채널 활성 확인 (spec_03 10초 polling + LISTEN): 
    docker exec ... -tAc "SELECT pid, application_name, query, state FROM pg_stat_activity WHERE query LIKE '%LISTEN%';"
  3. AlarmMonitor 로그: 
    docker logs rpi-finished-reflex-app 2>&1 | grep -i alarm | tail -40
  4. 원천 데이터 (influx_hist) 적재 확인: 
    ... -tAc "SELECT now() - MAX(time) FROM influx_hist;"
    > 10분 차이면 timeseries-pipeline 또는 외부 ingest 멈춤.
  5. 임계 규칙 변경 가능성 — 룰 테이블 점검 (spec_03).

검증

  • 5분 내 신규 알람 1건 이상 발생 확인 또는 강제 트리거 (테스트 임계 일시 변경)

롤백

임계 규칙 임시 변경했다면 원상 복귀.

알려진 함정

  • _polling_task zombie — spec_02 발견 사항. reflex-app long-uptime 시 task가 silently die. 일 1회 자동 재시작이 임시방편.
  • NOTIFY 큐 overflow — 짧은 시간 대량 알람이면 일부 drop 가능. polling fallback이 필요.
